# 通信対戦・クロスプレイの調べた結果(2026-11-12)

## できていること(試験で確かめた)
- 規則と CPU は Android 版と同じ Kotlin のコード。全30ゲーム×3つの種で、毎手の合法手・得点・結果のハッシュが JVM と JS で一致(94行)。CPU の最初の6手を入れても一致。
- 席の並べ替え(Android 版は `java.util.Random`)を、同じ計算(`JavaRandom`)で JS に移し、一致。
- 通信の部品(SHA-256・HMAC・AES-GCM・CRC32・Base64・deflate)を自前で書き、JDK(Android 版が使うもの)と 60 回のランダムな入力で一致。返信コードの暗号は、JDK で作ったものを自前の実装が開け、自前で作ったものが JDK と同じ文字列になる。
- 招待コード(短縮形式 `AS2O-`)の作成と解析が JVM と JS で同じ出力。
- ブラウザ(Chromium)2つで、招待コード → 返信コード → データチャネルが開く → 部屋 → 対局 → 交互に指す、まで通った。両画面の石の数が一致。

- Android 版 0.5.11 の再生の記録(30ゲーム×3つの種=90本)を Web 版の規則で再生し、全手が合法・勝者と得点が一致。
- 通信の手順 2(HELLO|名前|手順番号|規則の番号、WELCOME、COMPAT、チャット)は Android 版の `OnlineRoom.kt` そのまま。ブラウザ2つで、入室・チャット・対局を確認。

## 未確認
- **ブラウザから ntfy(中継)へ**: このセッションの環境が ntfy.sh を止めるので試せない。ntfy は CORS を許す作りのはずだが、実機で確かめる必要がある。通らなければ、返信コードの手入力(手動)だけは使える。
- **Android 版とブラウザの実機どうしの接続**: 同じ形式(短縮形式・negotiated データチャネル id=0・text フレーム)で作ったが、実機どうしは未確認。
- **mDNS**: Chrome は自分のローカル IP を `xxxx.local` に隠す。短縮形式は IP の数値しか持てないので、その候補は捨てられ、公開 STUN で得た外側のアドレスだけが残る。同じ Wi-Fi の中では、ルーターによってつながらないことがある(要実機)。
- **携帯回線どうし(TURN なし)**: Android 版と同じ構造上の限界。つながらない組み合わせがある。
- Safari・Firefox での動作。

## 公開ページ(Artifact)について
Artifact の公開ページは WebRTC・外部への通信ができない決まりなので、通信対戦はそこでは動かない。通信対戦を試すには GitHub Pages など、普通の Web サーバーに置く必要がある(`.github/workflows/pages.yml` に手動実行用の流れを用意してある)。

## 手順 2 の機能で未確認のもの
- 「待った」(依頼・了承・断り)、チャットのスタンプの絵、時間切れ(ホストが決めた手を受け取るだけの作りだが、Android 版のホストとの実機での確認はまだ)、古い版との接続。

## アプリ版との対戦の見直し(2026-11-12、0.5.11 との比べ)
| 項目 | Android 版 | Web 版 | 判定 |
|---|---|---|---|
| 部屋・手の受け渡し・待った・チャット・再戦 | `OnlineRoom.kt` | 同じファイルの写し(JS で動かない2か所だけ置き換え) | 同じ |
| 手順番号・規則の番号 | `Compat.PROTOCOL = 2`、RULES 全部 1 | 同じ。ただし画面のない4ゲーム(麻雀・道のりすごろく・スピード・ソリティア)は 0 を名乗る | 4ゲームは Android 版のホストの部屋で「版が違う」として選べなくなる(遊べないゲームが始まるのを防ぐ) |
| 招待コード・返信コード | `InviteCodec`(AS2O-/AS2A-、全体形式 AS1O-/AS1A-) | 同じコード。JVM と JS で同じ出力、JDK の deflate・CRC32・Base64 とも一致 | 同じ |
