## 1. 何を作るのか(ルール画面の形)
- ルール画面(`js/app.js` の `fillRuleSteps`)は**このままの形**で使う(ユーザーが「周りの UI は OK」と言っている)。
  上段: 左にステップの一覧・右に動画(16:9 の枠。動画が終わると次のステップへ自動で進む)。下段: 補足 → ローカルルール → コツ。
- 作るのは、**ステップごとの短い動画**(1 本 20〜45 秒)と、**ステップの文・補足**の書き直し。
- 動画は、**実際のアプリの対局画面**(左上の戻る・右の側板・左下の歯車も入った PC 版の画面)を録って、その上に注釈を重ねる。作り物の画面・独自の盤は使わない。
- ステップの数は自由(ユーザー:「多少項目が増えてもいいので、分かりやすさ、見やすさを最優先」)。マンカラは 6、大富豪は 8 にした。

## 2. 以前の動画の、だめだった所(ユーザーの指摘。二度と繰り返さない)
2026-11-28 にユーザーが指摘した、以前の動画(`docs/mockups/rules-video/NOTES.md` の作り方で作った物)の問題点。**今もほかのゲームの動画はこの状態**なので、作り直す時はすべて直す。

| だめだった所 | 具体的に何が起きていたか | どう直したか |
|---|---|---|
| 操作の一部のステップしか無い | マンカラは「種まき・倉でもう一度・横取り」の 3 本だけ。終わり方・勝ち方・相手の倉を飛ばす、が動画に無かった | ゲームを最初から最後まで遊べるだけのステップを全部作る(項目は増えてよい) |
| 何をするゲームか、の説明が無い | いきなり操作の説明から始まる | **1 本目は必ず「何をするゲーム?」**。盤の見方(自分の物・相手の物・場)と、勝ち方 |
| 専門の言葉をいきなり使う | 例: 麻雀(副露・ツモ・翻・符…)、マンカラ(倉・横取り)を説明なしで使っていた | 専門の言葉は、**初めて出た所で「」に入れて、その場で説明**する(「場の札が片づけられ(「場が流れる」)…」) |
| 矢印と吹き出しのとげが両方ある | 吹き出しにとげ(しっぽ)が付き、さらに矢印も付いていて不自然 | 説明の文は**とげの無い札**。矢印は「動きの向き」を見せる時だけ。文と矢印を両方付けない |
| まだ何も無い所を指す | 矢印が先に出て、その後で石・札が来る/石が動いた後の空の穴を指す | **差す物が画面に出てから**囲む・指す。動いた後に、もう空の所を指さない |
| カットインと同時に説明が出る | 「+4 横取り!」の演出と説明の文が同時に出て、どちらも読めない | カットイン・盤の演出の間は**文も番号も出さない**。説明はその前か後 |
| カットイン・終わった後の画面の上に矢印 | 結果の画面の上から矢印が出て、何も見えない | カットイン・結果の画面が出ている間は、注釈を**自動で全部隠す**(道具が見張る) |
| 手が早すぎる | 操作がぱっぱと進み、何が起きたか追えない | アプリの「ゆっくり」をさらに 1.25 倍ゆっくり。操作の前に説明し、操作の後に間を取る。文は 4 秒以上 |
| 矢印・説明文の品質が低い | 細い線・小さい文字・下の帯の文 | 道具(`overlay.js`)の注釈だけを使う(太さ・影・色・字の大きさが決めてある) |
| 動画の外に黒い帯 | 1280×800(16:10)で録っていたので、16:9 の枠に黒い帯 | **1280×720** で録る |

作った後にユーザーが追加で指摘したこと:

## 3. ユーザーが要望したこと(まとめ)
- 分かりやすさ・見やすさを最優先。項目(ステップ)は増えてよい。
- 1 本目は「何をするゲームか」。
- 専門の言葉は説明してから使う。
- 矢印と吹き出しのとげを両方付けない。
- 表示のタイミングを合わせる(まだ無い物を指さない)。
- カットインと説明を同時に出さない。カットイン・終わった後の画面の上に注釈を出さない。
- ゆっくり(ルール説明の動画なので)。
- 名札をほかの物にかぶせない(今後も)。
- 盤面を録画するのは良い(作り物にしない)。周りの UI(左のステップ・下の補足など)はそのまま。

## 4. 雰囲気(見た目・言葉)
- **言葉**: やさしい日本語の「です・ます」。1 つの文に 1 つのこと。子どもでも分かる言い方(「倉に石を多く集めた方が勝ちです」「場の 3 より強い札を、1 枚出します」)。
  - 強調したい言葉は `<em>` で囲む(オレンジの太字になる)。1 文に 1〜2 か所まで。
  - 「〜すると…」で区切り、次の映像で答えを見せる形がよい(「まいた最後の 1 個が、空っぽの自分の穴に入ると…」→ 動き → 「これが『横取り』です」)。
  - 見れば分かることは書かない。書くのは、見ただけでは分からない決まり(なぜそうなったか・何と呼ぶか・次に何が起きるか)。
- **テンポ**: 落ち着いた速さ。操作の前に説明 → カーソルがゆっくり動いて押す → 結果を見せる間 → 次の説明。1 本 20〜45 秒。
- **注釈の色と形**(道具が決めている。変えない):
  - 注釈の色は青 `#1F9BFF`(白いふち・影つき)。「とばす」「だめ」は赤 `#E8432E` の点線。
  - 説明の文: 白い札・左に青い線・丸ゴシック(Zen Maru Gothic)太字 28px。強調はオレンジ `#D9541A`。
  - 囲み: **差す物と同じ形・ほぼ同じ大きさ**(穴なら円、倉ならだ円、札なら角丸の四角)。ふわっと出て、ゆっくり明滅。
  - 名札: 白地・青ふちの丸い札(とげ無し)。差す物のすぐ外の、空いた所に置く。
  - 番号(1・2・3…): 石を入れた順など、順番を見せる時だけ。
  - 矢印: 動き・順番の「向き」だけ。線を引くように出て、引き終わってから矢じりが付く。
  - カーソル: 白い矢印のマウスカーソル。人の操作を見せる時に、ゆっくり動いて押す(押すと青い波紋)。
- 盤そのもの(アプリの絵・動き)をよく見せる。注釈は必要な物だけ。

## 5. 君(作る AI)が気をつけること(Claude が気をつけたこと)
1. **先にゲームを理解する**: 今のルール文・盤の描き方・core の規則(オプションの既定値)を読む。分からない規則は core を動かして確かめる(例: マンカラの終わり方は「残った石はその列の持ち主の倉へ」だった)。今の文の誤りも直す(マンカラの「右回り」は誤りで、実際は反時計回り)。
2. **ステップを設計してから録る**: 何を・どの順で・どの局面で見せるかを先に決める。1 本で教えることは 1 つ。
3. **局面は台本で作る**: CPU の手も台本どおりにし、配り方(seed)も決める。見せたい場面(横取り・革命・上がり・交換など)が自然に起きる手順を、core をシミュレーションして探す(`mancala-sim.cjs`・`daifugo-sim.mjs`・`daifugo-plan.mjs` が見本)。手順は必ず規則どおりか確かめる(録画の道具は、局面が台本と違うと止まる)。
4. **時間の順番**: 説明(前ふり)→ 操作 → 盤の動き・カットイン(注釈なし)→ 落ち着いてから説明(まとめ)。
5. **かぶりを避ける**: 名札・説明の文は空いた所に。かぶる所しか無ければ盤の外(差す物の上側など)へ。`T.avoid([...])` で避ける物を必ず決める(かぶったら録画が止まる)。
6. **説明の文の置き場所**: 盤の下が空いていればそこ(マンカラ)。空いていなければ右の側板の空いた欄(大富豪。`T.capBox`)。卓の上に文を置いて札・駒を隠さない。
7. **録ったら必ずコマで確かめる**(下の 7 章)。文が出る時刻・差す物が出ている か・カットインと重ならないか・かぶり・字の折り返し。だめなら直して録り直す。**1 本ずつ見て、全部直るまで繰り返す**。
8. **見せる前に自分で 2 回見直す**。ユーザーに「OK」と言われるまでが仕事。
9. 時間をかけてよい。Claude はマンカラ・大富豪それぞれに 1〜2 時間かけた(調べる・手順を探す・台本・録る・コマで確かめる・直す、を何度も繰り返した。1 本録るだけで 3〜4 分かかる)。

## 7. コマで確かめる方法(必ずやる)
```bash
# 1.5 秒ごとのコマを 4 列に並べた 1 枚の絵(全体の流れ・文の出る時刻)
ffmpeg -v error -y -i out.mp4 -vf "fps=1/1.5,scale=560:-1,tile=4x6" -frames:v 1 sheet.png
# 気になる時刻を大きく 1 枚(字の折り返し・かぶり)
ffmpeg -v error -y -ss 12 -i out.mp4 -frames:v 1 -vf scale=960:-1 one.png
```
確かめること:
- 先頭のコマが対局中の盤(メニュー・設定・「対局開始」のカットインが映っていない)。
- 文・囲み・名札・矢印が、**差す物が出てから**出ている。動いた後の空の所を指していない。
- カットイン(「あなたの番です」「革命」など)・盤の演出(「+6 横取り!」など)・結果の画面の間、注釈が出ていない。カットインで文が途中で隠れて終わっていない(→ カットインが消えてから文を出す)。
- かぶり: 名札・文・番号が、札・駒・穴・数の札・席・ボタン・ほかの注釈にかかっていない。囲みが数の札などにかかっていない。
- 字: 言葉の途中で折り返していない(「ジョー/カー」は NG)。文が枠からはみ出ていない。
- 速さ: 文を読み終わる前に次へ行っていない(1 つの文は 4 秒以上)。
- 終わり方: 最後の文のあと、少し間があって終わる。

## 8. 道具(tools/rule_video)の使い方
### engine.cjs(Node 側)
- `launch()`: Chromium を開く。ページの時計(setTimeout・rAF・performance.now・CSS の動き)を 0.25 倍で流し、重い描画でもコマ落ちしないようにする。
- `openGame(env, id, setupFn, { seed, cpuQ, hold })`: メニュー → 設定 → スタート。設定はアニメーション「ゆっくり」・カットインあり。
  - `seed`: 配り方を決める(`newMatchNamed` の seed を差し替える)。
  - `cpuQ`: **CPU の手を、CPU が考え始める前に全部入れておく**(後から入れると、CPU が自分で考えた手を打ってしまう)。
  - `hold`: 最初から CPU を止めておく(`window.__hold`。台本で 1 手ずつ進める)。
  - ほかに `window.__holdResult = true` で結果の画面を止めておき、`window.__resultPending()` で出す(終わりの説明をしてから結果を出すため)。
- `replay(env, moves, who, { queued })`: 見せない手を、アニメーションとカットインを止めて速く進める。`who[k]` は k 手目が人の手か。
- `record(env, out, scenario, args, K)`: 画面を録り、注釈を入れて mp4 にする。`K = 0.8`(動画ではアプリの「ゆっくり」をさらに 1.25 倍ゆっくりに見せる)。

### overlay.js(ページの中。`T`)
- 時間はすべて「動画の上の時間(ミリ秒)」: `T.sleep(ms)`・`T.until(fn)`
- `T.cap(html)`: 説明の文(1 つだけ。入れ替える時はいったん消してから出す)。`T.cap(null)` で消す。`T.capBox = {left, top, width, maxH}` を決めると、その欄(右の側板など)に出す。
- `T.ring(id, 形, {ng, dash})`: 囲み。形は `{el}`(部品)・`{els}`(いくつかをまとめて)・`{page:{x,y,w,h,rr}}`・盤の SVG の座標(マンカラ)。
- `T.label(id, 文, 場所, {for, ng})`: 名札。`for` に自分の囲みの id を入れると、その囲みとはかぶりを調べない。
- `T.badge(id, 番号, 場所)`・`T.arrow(id, path, {page, w})`・`T.cursorShow/cursorTo/press/cursorHide/cursorOn`
- `T.avoid([...セレクタ])`: **避ける物を決める。名札・文がそれやほかの注釈とかぶると、録画が止まる**(エラーの文に、何と何がかぶったかが出る)。
- `T.clear(...ids)`・`T.clearAll()`
- カットイン(`#cutlayer .cutin`)・結果の画面(`#result`)が出ている間は、注釈を自動で隠す。

### ゲームごとの小道具(台本の中の `HELP`)
- `M.click(pit)`・`M.badges()`(マンカラ: 石の落ちる順に番号)、`D.pick(cardIds)`・`D.press('出す')`・`D.cpu()`(1 手だけ進める)・`D.myTurn()`(自分の番になり「あなたの番です」が消えるまで待つ)・`D.calm()`(大富豪)。新しいゲームでは、同じ考え方で作る。

## 9. 落とし穴(実際に引っかかった所)
- **CPU の手**: 台本の CPU の手は、始める前に全部 `cpuQ` に入れる。CPU は考えた後に `modalPause()` で待つので、`__hold` で止めても、考えた手(台本の手)は変わらない。
- **3 人以上のゲーム**: 自分の番が来るたびに「あなたの番です」のカットインが出る。その間は注釈が隠れるので、文はカットインが消えてから出す(`D.myTurn()`)。
- **名前のぶつかり**: 注釈の部品にアプリと同じクラス名(例 `.side`)を付けると、アプリの CSS が効いて崩れる。注釈のクラスは必ず `tut-` で始める。
- **字の折り返し**: アプリは `word-break: auto-phrase`。注釈の `em` は `display:inline` にしてある。変えない。
- **字の形**: 丸ゴシックの太字(700)は使う字だけに絞ってある(約 1300 字)。台本の文の字がすべて入っているか確かめる(`fontTools` で `web/pc-firebase/fonts/ZenMaruGothic-Bold.woff2` の cmap を見る)。無い字は別の書体で出てしまう。
- **出る途中の大きさ**: 囲み・名札はふわっと拡大しながら出るので、かぶりは出し終わった大きさで調べる(道具が対応済み)。
- **数の札などが先に変わる**: マンカラは押した瞬間に穴の数の札が最後の数になる(アプリの動き)。番号の注釈は石が落ちた時刻に出す。
- **矢じり**: 線を引くように出す時、矢じりは引き終わってから付ける(先に矢じりだけ出ない)。道具が対応済み。
- **アプリの不具合が見つかることがある**(大富豪の「革命」のカットインが出なかった)。勝手に直さず、ユーザーに伝えて確認する。
- **ローカルの動画の試験**: python の http.server では動画の途中へ飛べない(上の 6 章 9)。
